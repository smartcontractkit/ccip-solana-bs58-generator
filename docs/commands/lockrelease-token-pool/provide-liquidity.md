# lr provide-liquidity

Deposit tokens from the rebalancer into the pool's token account, backing release on inbound transfers.

**Preconditions:** Three gates, in order: a rebalancer must be set, can-accept-liquidity must be true, and the rebalancer's token account must have approved the POOL SIGNER PDA as delegate (the program moves tokens by CPI with that PDA as authority). That approval is NOT one-time setup: the transfer spends it and SPL clears the delegate at zero, and a ccipSend approves the router's fee-billing signer on the same account, replacing it. Approve immediately before each provide-liquidity, or pass --auto-approve to put both in one transaction.

## Invocation

```bash
cct-solana-tx lr --instruction provide-liquidity --env devnet [flags]
```

## Flags

| Flag | Arg | Required | Description |
| --- | --- | --- | --- |
| `--program-id` | programId | yes | Lockrelease token pool program ID (required for all instructions) |
| `--mint` | mint | yes | Token mint address (required for all instructions) |
| `--authority` | authority | yes | Authority address (required for all instructions) |
| `--amount` | amount | yes | Amount to provide/withdraw (in smallest token units) (required for provide/withdraw-liquidity) |
| `--auto-approve` |  | optional | provide-liquidity only: prepend the SPL Approve for the pool signer PDA, so the delegation cannot be spent or replaced before the transfer |

## Failure modes

Missing rebalancer -> Unauthorized 6002. Liquidity disabled -> LiquidityNotAccepted 6020. Missing, spent or replaced delegate approval -> SPL Token OwnerMismatch (custom program error 0x4) raised inside the CPI, naming neither the delegate nor the amount; the CLI checks the delegation first and prints the account state instead.
